# 缓存、续传与已知限制

## 缓存和文件复用

缓存位于输出文件旁的 `video.mp4.parts/`。失败或取消时保留已完成分片，成功后默认删除；启用 `keep_parts` 可继续保留。

原生 HLS 缓存按分片大小和清单指纹复用。清单发生变化时停止复用，保留旧缓存；不自动把不同签名地址合并为同一来源。分片记录不保存源 URL、请求头或 Cookie；AES-128 密钥会以本机文件保存在缓存中，不应分发缓存。

完整且通过缓存检查的原生 HLS 可离线重新合并。该检查主要核对记录和文件大小，不等同于逐字节校验或媒体全帧解码。

同一地址、同一输出目录可复用已有任务。已完成文件通过路径、非零大小和纳秒修改时间核对；被修改或清空的文件不再作为完成结果复用，Web 新任务会避让已有文件。该检查不计算整文件哈希，无法检测大小和修改时间均被刻意恢复的改动。

`.task-index.json` 只保存来源哈希、输出路径及文件元数据。完整任务卡和请求头保存在服务内存中，重启后不会恢复全部任务历史；索引和缓存不等同于任务历史。

## 原生 HLS

支持静态 TS HLS 点播、无独立音轨的多码率清单及 AES-128。多码率清单按声明带宽选择最高项，没有手动画质选择器。

直播、字节范围、fMP4、独立音轨和其他加密格式会尝试兼容流程。携带超出兼容流程允许范围的请求头时会停止，不把凭据交给 FFmpeg。DRM 授权获取和解密不在支持范围内。

跨站分片、密钥或重定向如果需要鉴权，必须明确配置可信来源。不能因为资源出现在清单中就自动信任其站点。

## 兼容续传

兼容流程输出 MPEG-TS 分段，以媒体时间点续传，并回退一小段时间后裁剪接缝。

- seek 落点受关键帧和源分片影响，接缝可能存在误差。
- 单文件 MP4 是否节省重复流量，取决于源站是否支持 HTTP Range。
- 签名链接失效、直播窗口移走后，旧任务可能无法继续。
- 网络取消受当前请求与子进程退出时间约束，不保证瞬时完成。
- 源时长未知时无法核对完整覆盖；页面会提示人工检查。

最终校验包括输出可读取和时长比较，不保证每帧画面、每段音频都无损坏。关闭严格校验会允许更多容错，应检查结果。

## 平台和其他边界

- 服务只面向单用户本机使用，不提供远程部署、多用户权限或长期历史管理。
- Windows / Linux 启动和文件夹选择代码已提供，尚未完成完整实机验证。
- 当前完整测试使用 Python 3.14.7、FFmpeg 9.0.1；旧 FFmpeg 可能不支持部分兼容选项。
- 网络速度按接收或写入字节估算，并非精确的系统流量计数。
- `video_downloader/cli/resume_dl.sh` 是历史参考，不与 Python 引擎保持功能同步，缓存不能混用。它会记录 FFmpeg 原始错误，仅适合不含私人凭据的输入。
